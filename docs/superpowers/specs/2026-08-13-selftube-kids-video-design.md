# SelfTube — родительский фильтр видео для детей

**Дата:** 2026-08-13
**Статус:** согласованный дизайн, готов к планированию реализации

## Проблема

Ребёнок смотрит видео в Яндекс.Видео. Основная претензия — в рекомендациях появляются нежелательные видео (монстры, стрелялки и т.п.). Цель проекта — **фильтр**: ребёнок видит только то, что заранее одобрил родитель, без алгоритмических рекомендаций, ведущих к постороннему контенту. По интерфейсу и ощущению — похоже на YouTube/Rutube/Яндекс.Видео, но своё видео мы не загружаем: оно проигрывается из внешних источников через встраиваемые плееры.

## Ключевые решения (согласованы с заказчиком)

- **Модель каталога:** и целые каналы (с автопополнением), и отдельные видео.
- **Платформы:** в v1 — **только Rutube**. Архитектура с «адаптерами платформ», чтобы VK и Одноклассники добавить позже без переделки ядра. (VK требует OAuth-приложения; у Одноклассников нет публичного API для списка видео канала — см. «Исследование».)
- **Масштаб:** сейчас — одна семья (самохостинг), но архитектура «SaaS-готовая» (всё привязано к `Account`).
- **Устройство ребёнка:** планшет/телефон, браузер → адаптивный веб (PWA).
- **Профили:** один общий список на всех детей (без профилей в v1).
- **Изоляция:** **максимально строгая** — ребёнок не должен иметь возможности перейти к рекомендациям ни через переход со страницы, ни через клик по «похожему» внутри плеера.
- **Функции ребёнка в v1:** поиск по каталогу + дневной лимит времени. (Категории и история просмотра — не в v1.)
- **Авторизация:** только для родителя (вход в админку). Детская часть на устройстве открывается без логина.
- **Стек:** Next.js (App Router) + TypeScript + SQLite (Prisma) + Tailwind. SQLite → Postgres при переходе к SaaS.

## Исследование платформ (обоснование выбора Rutube для v1)

Проверено веб-исследованием (2025-2026):

| Возможность | Rutube | VK Видео | Одноклассники |
|---|---|---|---|
| Список видео канала (автопополнение) | ✅ публичный JSON API, без ключа | ⚠️ есть, но нужен OAuth user-token, лимит ~3 rps | ❌ публичного read/list API нет |
| Метаданные видео (название/обложка/длительность) | ✅ полные | ✅ | ⚠️ только oEmbed (без длительности) |
| JS-управление плеером (для «Безопасного плеера») | ✅ документированный postMessage API | ⚠️ ограниченный js_api | ❌ не документирован |
| Встраивание iframe | ✅ (нет X-Frame-Options) | ✅ (нужен `hash` из API) | ✅ (`nochat=1`) |

**Общий вывод:** ни одна платформа не даёт параметра, отключающего «похожие видео» внутри плеера. Изоляция достигается на нашей стороне (sandbox + своя оболочка — см. «Безопасный плеер»). Rutube — самая пригодная платформа по всем осям, поэтому v1 строится на нём.

**Полезные эндпоинты Rutube (публичные, без ключа, но неофициальные — кешировать и обрабатывать сбои):**
- Метаданные видео: `GET https://rutube.ru/api/video/{VIDEO_ID}/` → `title`, `duration` (сек), `thumbnail_url`, `embed_url`, `author.id`, `is_adult`, `age_range`, `pg_rating`.
- Видео канала/автора: `GET https://rutube.ru/api/video/person/{AUTHOR_ID}/?page=N` → пагинированный список.
- oEmbed: `GET https://rutube.ru/api/oembed/?url={URL}&format=json` (без длительности).
- Встраивание: `https://rutube.ru/play/embed/{VIDEO_ID}`.
- Плеер postMessage API: команды `player:play`, `player:pause` и др., события `playComplete`, смены состояния.

*Замечание по рискам:* API Rutube внутренний/неофициальный — может измениться. Метаданные кешируем, ошибки обрабатываем мягко. Реальное поведение плеера (что кликабельно в конце) проверяем спайком до основной разработки.

## Архитектура

Один Next.js-проект (App Router) с явным разделением слоёв, чтобы доменная логика не зависела от фреймворка (SaaS-готовность и тестируемость).

```
Веб (React/Tailwind)              Сервер (Next API routes / server actions)
├─ Детская часть  (/)             ├─ Auth        — вход родителя, сессия-cookie
│  ├─ Главная (сетка видео)       ├─ Catalog     — что одобрено (видео/каналы)
│  ├─ Поиск по каталогу           ├─ Sync        — тянет новые видео каналов
│  └─ Безопасный плеер            ├─ TimeLimit   — учёт и лимит времени/день
└─ Админка  (/admin)             └─ PlatformAdapter (интерфейс)
   ├─ Логин                          └─ RutubeAdapter (v1)
   ├─ Каналы / Видео (добавить/убрать)   (Vk/OkAdapter — позже)
   └─ Настройки (лимит времени)

Доменный слой (чистый TS, без Next):        Данные:
├─ catalog-service                          SQLite через Prisma
├─ platform-adapter (интерфейс + Rutube)    (→ Postgres для SaaS)
└─ timelimit-service
```

### Границы модулей

- **PlatformAdapter** — интерфейс: `resolveVideo(url)`, `listChannelVideos(channelId)`, `getEmbed(videoId)`, `resolveChannel(url)`. В v1 одна реализация — `RutubeAdapter`. Добавление VK/ОК = новая реализация, ядро не меняется. Всё платформо-специфичное (форматы URL, парсинг ответов) живёт только внутри адаптера; остальная система работает с внутренними моделями `Video`/`Channel`.
- **CatalogService** — единственный источник правды о том, что можно смотреть ребёнку. Детская часть читает только отсюда и **никогда** не ходит в интернет за рекомендациями напрямую. Это и есть фильтр.
- **SyncService** — опрашивает одобренные каналы через адаптер и добавляет новые видео. В v1: по кнопке в админке + простой фоновый интервал (без сложного планировщика).
- **TimeLimitService** — учёт просмотренного времени за день и решение «можно ли ещё смотреть».
- **Auth** — вход родителя (email+пароль, bcrypt), сессия в cookie. Защищает `/admin`.

## Модель данных (SQLite через Prisma)

`Account` — корень (в v1 одна запись); всё привязано к нему для будущего мультиарендного SaaS.

```
Account            id, createdAt
Parent             id, accountId, email, passwordHash, createdAt
Channel            id, accountId, platform (RUTUBE), platformChannelId,
                   title, thumbnailUrl, enabled, lastSyncedAt, addedAt
Video              id, accountId, platform, platformVideoId,
                   title, thumbnailUrl, durationSec, embedUrl,
                   sourceType (MANUAL | CHANNEL), channelId (nullable),
                   hidden (bool), publishedAt, addedAt
                   @@unique(accountId, platform, platformVideoId)
Setting            accountId, dailyLimitMinutes (nullable = без лимита)
DailyUsage         accountId, date (YYYY-MM-DD), secondsWatched
                   @@unique(accountId, date)
Session            id, parentId, expiresAt
```

### Правила данных

- **Каталог для ребёнка** = все `Video` данного account, где `hidden=false` и (если из канала) канал `enabled`.
- **Ручное видео** (`sourceType=MANUAL`): `channelId` пустой; синхронизация его не трогает.
- **Видео канала** (`sourceType=CHANNEL`): создаётся `SyncService`. Родитель может скрыть точечно (`hidden=true`); синхронизация уважает это и не «воскрешает».
- **Лимит времени**: детский плеер шлёт «пульс» раз в N секунд во время проигрывания → сервер копит `secondsWatched` за сегодня в `DailyUsage`. При достижении `dailyLimitMinutes` плеер блокируется до завтра. Счётчик **общий на семью/день** (профилей нет).

## Безопасный плеер (ключевой и самый рискованный компонент)

«Своя оболочка поверх чужого плеера». **Строится первым (спайк)** — проверяется на живых видео Rutube до основной разработки; если что-то из JS-API недоступно, подход корректируется, пока цена мала.

1. **Sandbox-изоляция (не уйти с сайта):**
   ```html
   <iframe src="https://rutube.ru/play/embed/{id}"
           sandbox="allow-scripts allow-same-origin"
           allow="fullscreen; encrypted-media"
           referrerpolicy="strict-origin-when-cross-origin">
   ```
   Нет `allow-popups` и `allow-top-navigation` → клик по ссылке внутри плеера не уводит страницу и не открывает вкладку.
2. **Своя оболочка (не кликнуть «похожее» внутри плеера):** прозрачный слой поверх iframe перехватывает **все** касания, родной UI плеера (логотип, сетка рекомендаций, ссылки) недоступен. Управление — только нашими кнопками (play/pause, перемотка, громкость, полный экран, «назад») через Rutube postMessage API.
3. **Защита конца видео:** по событию `playComplete` мгновенно закрываем iframe своим экраном «Видео закончилось» с подборкой **из нашего каталога** — родная сетка рекомендаций не успевает стать кликабельной.
4. **Fail closed:** если плеер не ответил на JS-«рукопожатие» за таймаут — видео **не показываем**, выводим «видео временно недоступно». Лучше не показать, чем показать неконтролируемый плеер.

## Интерфейс

- **Детская главная (стиль «детский»):** крупные яркие скруглённые карточки, дружелюбный маскот, большие тач-цели. Сверху — поиск, справа — остаток времени. Сетка одобренных видео.
- **Поиск:** только по каталогу (одобренные видео), не по всему Rutube.
- **Безопасный плеер:** свои крупные контролы; экран «видео закончилось» с подборкой из каталога.
- **Админка (`/admin`, утилитарный стиль):** вход email+пароль. Одно умное поле «вставьте ссылку» само определяет канал/видео. Разделы: одобренные каналы (с автопополнением, счётчиком видео, временем синхронизации, вкл/выкл, удалением), отдельные видео (со «скрыть»), кнопка «Синхронизировать», вкладка «Настройки» (лимит времени в день).

## Обработка ошибок

- **Rutube API недоступен/изменился:** метаданные кешируем в БД; при сбое синхронизации показываем в админке предупреждение, каталог продолжает работать на закешированных данных.
- **Видео удалено/приватно на источнике:** плеер по fail-closed показывает «видео недоступно»; помечаем такие видео в админке для внимания родителя.
- **Плеер не отвечает на JS-API:** fail closed (см. Безопасный плеер).
- **Неверная ссылка в админке:** валидация и понятное сообщение, что ссылка не распознана как видео/канал Rutube.

## Тестирование

- **Доменный слой (юнит-тесты, чистый TS):** `catalog-service` (правила видимости, `hidden`, `enabled`), `timelimit-service` (накопление, сброс по дню, порог), `RutubeAdapter` (парсинг URL и ответов API — на зафиксированных фикстурах).
- **Безопасный плеер:** ручная проверка спайка на живых видео + автотест на fail-closed (нет ответа → блокировка).
- **Интеграционные:** добавление канала → синхронизация → появление видео в каталоге ребёнка; достижение лимита → блокировка плеера.

## Границы v1 (YAGNI)

Не входит в v1: VK и Одноклассники; профили детей; категории/подборки; история просмотра; мобильные нативные приложения; сложный планировщик синхронизации; мультиарендный SaaS (архитектурно заложен, но не активируется).

## Порядок реализации (предварительно)

1. Спайк «Безопасного плеера» на Rutube (снятие главного риска).
2. Каркас проекта: Next.js + Prisma + Tailwind, модель данных, `Account`/`Parent` seed.
3. `RutubeAdapter` + `CatalogService`.
4. Админка: авторизация, добавление канала/видео, список, скрытие/удаление.
5. `SyncService` (кнопка + интервал).
6. Детская часть: главная, поиск, интеграция «Безопасного плеера».
7. `TimeLimitService` + пульс + блокировка.
8. PWA-обёртка, финальная проверка изоляции.

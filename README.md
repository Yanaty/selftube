# SelfTube

SelfTube — это родительский фильтр видео для детей. Родитель самостоятельно
подбирает разрешённые каналы и отдельные видео с Rutube в админ-панели, а
ребёнок смотрит **только** то, что одобрено, в удобном YouTube-подобном
интерфейсе — без алгоритмических рекомендаций, «похожих видео» и бесконечной
ленты. В версии 1 поддерживается только Rutube, но архитектура построена на
платформенных адаптерах, поэтому позже можно добавить VK, OK и другие
источники.

На телефоне приложение устанавливается как PWA и называется **«Мультики»**;
`SelfTube` — имя проекта в репозитории. Иконку можно перерисовать скриптом
`node scripts/generate-icon.js public`.

## Технологии

- **Next.js 14** (App Router)
- **TypeScript**
- **Prisma + SQLite**
- **Tailwind CSS**
- **Vitest** (тесты)

## Установка и запуск

```bash
npm install
cp .env.example .env   # при необходимости поправьте DATABASE_URL
npm run db:push
npm run db:seed
npm run dev
```

После `npm run db:seed` создаётся аккаунт родителя по умолчанию:

- **Логин:** `parent@example.com`
- **Пароль:** `changeme123`

Значения можно переопределить переменными окружения `SEED_PARENT_EMAIL` и
`SEED_PARENT_PASSWORD` перед запуском сида.

## Как пользоваться

**Родитель** работает в админ-панели по адресу `/admin`.

> **Как открыть админку из установленного приложения.** В режиме PWA адресной
> строки нет, поэтому вход спрятан в логотипе: **пять быстрых нажатий** по иконке
> слева от поиска (уложиться в 2 секунды) открывают окно с примером на умножение,
> и после верного ответа откроется админка. Пример нужен потому, что сессия
> родителя живёт несколько дней: без него ребёнок, случайно повторивший жест,
> попал бы прямо в настройки. Обратно — ссылка «← К мультикам» в боковом меню.

Что делать в админке:

1. Войдите под аккаунтом родителя.
2. Вставьте ссылку на канал, плейлист или отдельное видео Rutube, чтобы одобрить
   его. Для канала и плейлиста добавляются все видео целиком
   (`rutube.ru/channel/<id>/`, `rutube.ru/plst/<id>/`, `rutube.ru/video/<id>/`).
3. Нажмите **«Синхронизировать»**, чтобы подтянуть новые видео из одобренных
   каналов и плейлистов. Само это не происходит — автосинхронизация выключена.
4. В разделе **«Настройки»** задайте дневной лимит просмотра.

**Ребёнок** пользуется приложением по адресу `/` (главная):

- просматривает сетку одобренных видео;
- ищет видео внутри одобренного каталога;
- нажимает на видео, чтобы начать просмотр.

## Деплой на VPS (Docker + Caddy)

Подойдёт любой VPS с KVM-виртуализацией и root-доступом. HTTPS выпускает Caddy
сам — без него приложение не установится на телефон как PWA.

**1. Домен.** A-запись домена должна указывать на IP сервера. Проверить:
`dig +short ваш-домен` — должен вернуться IP VPS.

**2. Образ.** Его собирает GitHub Actions и кладёт в GitHub Container Registry —
на VPS с 1 ГБ памяти своя сборка не помещается. Репозиторий приватный, значит и
образ приватный, поэтому серверу нужен доступ: в GitHub создайте токен
(Settings → Developer settings → Personal access tokens → classic) с единственным
правом **read:packages**.

**3. На сервере:**

```bash
# Docker (Ubuntu/Debian)
curl -fsSL https://get.docker.com | sh

git clone https://github.com/Yanaty/selftube.git && cd selftube
cp .env.deploy.example .env && nano .env      # домен, почта, пароль родителя

echo ВАШ_ТОКЕН | docker login ghcr.io -u ВАШ_ЛОГИН --password-stdin
docker compose pull && docker compose up -d
```

Первый запуск занимает минуту: скачивается образ, создаётся схема базы, заводится
аккаунт родителя, Caddy получает сертификат. Смотреть за процессом:
`docker compose logs -f`.

**4. Обновление** после новых коммитов — дождаться зелёной сборки в Actions и:

```bash
docker compose pull && docker compose up -d
```

Собрать образ прямо на сервере, если очень нужно (потребуется ~2 ГБ памяти):

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

База лежит в отдельном Docker-томе и пересборку переживает. Бэкап — обычное
копирование файла:

```bash
docker compose cp app:/data/dev.db ./backup-$(date +%F).db
```

## Деплой на Fly.io (альтернатива)

Приложению нужен Node-процесс и постоянный диск: база — это файл SQLite, который
надо где-то хранить между деплоями. Поэтому GitHub Pages не подходит вовсе, а
Vercel потребовал бы переезда на сетевую базу. Fly.io подходит без единой правки
в коде. Ничего фонового в процессе не крутится, поэтому машина засыпает без
запросов и просыпается на первый.

```bash
fly apps create ваше-имя        # имя глобально уникально; fly.toml уже в репозитории
# регион в fly.toml — fra (Франкфурт); список доступных: fly platform regions
fly volumes create multiki_data --size 1 --region fra   # диск в том же регионе, что и машина
fly secrets set SEED_PARENT_EMAIL=вы@почта SEED_PARENT_PASSWORD=длинный-пароль
fly deploy
```

При первом запуске контейнер сам создаёт схему (`prisma db push`) и аккаунт
родителя (`prisma/seed.ts`). Обе операции идемпотентны: на готовой базе они
ничего не меняют и **не сбрасывают пароль**.

Каталог можно не переносить — добавьте каналы и плейлисты заново, синхронизация
соберёт всё за пару минут. Если нужна именно текущая база со скрытыми видео:

```bash
fly sftp shell
put dev.db /data/dev.db
```

Базу в git класть не нужно (в `.gitignore` есть `*.db`): в ней лежат хеши паролей
и активные сессии, она меняется при каждой синхронизации, а на сервере всё равно
живёт своей жизнью.

### GitHub Actions

- **CI** (`.github/workflows/ci.yml`) — на каждый пуш: типы, тесты, сборка.
- **Docker image** (`.github/workflows/docker.yml`) — пуш в `main` собирает образ
  и кладёт его в `ghcr.io/yanaty/selftube:latest`. Секретов не требует: работает
  на встроенном `GITHUB_TOKEN`. Кроме `latest` ставится тег с хешем коммита —
  на него можно откатиться через `APP_IMAGE` в `.env`.

### Что сделать сразу после деплоя

1. Зайти в `/admin` и **сменить пароль** в настройках — если он остался
   стандартным, админка сама покажет красное предупреждение.
2. Проверить установку приложения на телефон: она требует HTTPS, а он у Fly есть.

## Ограничения версии 1

- **Только Rutube** (VK/OK планируются позже).
- **Один общий список** для детей — без отдельных профилей на каждого ребёнка.
- **Синхронизация только вручную** — кнопкой «Синхронизировать» в админке.
  Код периодического планировщика лежит в `src/lib/scheduler.ts` и отключён:
  включается раскомментированием двух строк в `app/layout.tsx`.
- **Одна семья** — архитектура готова к SaaS, но пока не мультитенантная.

## Проверка строгой изоляции (ручная)

После того как через `/admin` добавлено хотя бы одно реальное видео Rutube,
человек должен вручную проверить на настоящем устройстве/в браузере следующий
чек-лист:

1. На `/watch/<id>` нажатие по области плеера **не** уводит со страницы и **не**
   открывает новые вкладки (sandbox).
2. Собственный логотип Rutube, блок «похожих видео» и ссылки **не** кликабельны
   сквозь наш оверлей.
3. Когда видео заканчивается, появляется **наш** экран «Видео закончилось» с
   подборкой из каталога (а не сетка «похожих» от Rutube).
4. Удалённое/сломанное видео показывает «Видео временно недоступно»
   (fail-closed), а не неуправляемый плеер.
5. Детский поиск возвращает только элементы из одобренного каталога.
6. При достижении дневного лимита появляется «На сегодня всё!», и воспроизведение
   блокируется.
